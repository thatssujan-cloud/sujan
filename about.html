// about

I build things that work well for the people using them.

I got into building things for the web almost by accident — tweaking the CSS on a hobby forum in high school until three in the morning, just to get the layout right. That instinct never really went away.

These days I work across the design-to-development handoff: sketching flows, building the component library that supports them, and writing the front-end code that ships them. I like projects where those two halves inform each other — where a technical constraint improves the design, or a design decision simplifies the code.

Outside of client and product work, I contribute to a couple of open-source accessibility tools and spend an unreasonable amount of time tuning my terminal setup. I'm always happy to talk shop — reach out if you want to compare notes or explore working together.
